# Embedded domain-language workflow

Use this procedure when the unit contains overloaded terms, competing interpretations, or important learning concepts that need a shared meaning.

## Make terms precise

1. Read the existing unit map, tickets, and any local context files before introducing terminology.
2. Flag conflicts immediately. State the current meaning and the competing meaning, then ask which one should be canonical.
3. For fuzzy terms, propose a precise term and test it against concrete learner scenarios, including an edge case.
4. Record the resolved term in the unit's glossary or context file as soon as the human confirms it.
5. Keep the glossary about meaning and relationships, not implementation details or temporary planning notes.

## Useful distinctions

Test whether the unit is distinguishing:

- topic, big idea, learning intention, outcome, and success criterion;
- activity, learning experience, practice, assessment, and evidence;
- knowledge, skill, understanding, application, and transfer;
- support, differentiation, accommodation, modification, and extension;
- prerequisite, misconception, barrier, and observable error.

Do not force these distinctions when the context uses different valid terminology. The goal is shared language that makes the unit easier to design and teach.
