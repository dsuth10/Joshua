# Embedded prototyping workflow

Use this procedure for a HITL Prototype ticket. A prototype is a cheap, concrete artifact used to make a design decision easier for the human to react to.

1. State the design question the artifact is meant to answer.
2. Choose the smallest useful artifact: a unit outline, lesson card, assessment prompt, exemplar, rubric stub, activity flow, or visual.
3. Make assumptions visible and keep fidelity low enough that revision is easy.
4. Present the artifact with two or three targeted questions about what should change, remain, or be rejected.
5. Record the human's response as the ticket resolution and update the map with the resulting decision.

Do not polish a prototype into the final unit before the underlying decision is settled. Link the artifact from the ticket when the tracker or workspace supports it.
